# AGENTS.md

## Non-negotiable
- Read `codex/TASKS.md` first, then read `codex/CONTRIBUTING.md`, and follow both strictly.
- Instruction priority: `codex/TASKS.md` > `codex/CONTRIBUTING.md` > repository docs (for example `README.md`).
- If any instructions conflict or are unclear, stop and ask before proceeding.
- Keep changes minimal and within the Issue scope.
- You MUST confirm the Issue number explicitly before creating/switching branches.
- If the Issue number is not provided, STOP and ask: "What is the Issue number?"
- Do NOT start implementation or run builds until the Issue number is confirmed.

## Responsibility boundary (Codex)
- You are responsible for implementation, confirming `npm run build` succeeds, pushing the branch, and creating the Pull Request.
- You may create/switch branches only after confirming the Issue number.
- After a successful build, run these commands in order:
  - `git status`
  - `git add -A`
  - `git status`
  - `git commit -m "<auto-generated message>"`
  - `git push -u origin HEAD`
- Create the Pull Request with `gh pr create` and use the PR template structure below for the body:
  - Summary
  - What changed
  - How to verify
  - Scope
  - Risks
  - Follow-ups
  - Open Questions
- Do NOT push directly to `main`.
- Do NOT use force-push unless the user explicitly asks for it.
- If `gh auth` or network access fails, stop, report the failure clearly, and provide the PR body so a human can complete the remaining external step.

## Build
- Run `npm run build` before considering the task complete.
